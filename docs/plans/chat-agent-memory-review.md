## 当前结构

ChatPage 负责会话选择、前端历史组装、发送、编辑重发和引用展示；useStreamingChat 负责请求与流式状态；backend/chat/router.py 同时负责上下文策略、普通聊天、RAG 工具循环、消息保存、引用处理和后台摘要。

现有 Agent 能力是 RAG 中的知识库搜索工具循环。检索有结果后切换到无工具的回答生成，尚无独立的通用 Agent 执行层、任务记录或长期记忆服务。

Conversation.summary 是会话摘要字段；知识库索引面向导入文档。当前没有跨会话记忆条目、对话知识索引、来源版本或记忆失效机制。现有代码中的摘要与历史压缩不能直接当作长期记忆。

## 建议的职责划分

1. **Chat**：会话、消息、编辑历史和交互展示，保留原始内容与来源；不承担记忆提炼策略。
2. **ContextBuilder**：从数据库读取选定会话的有效历史，组合滚动摘要、相关记忆和文档检索证据，并控制预算。普通 Chat 与 Agent 共用。
3. **AgentRunner**：执行模型与工具循环，管理运行状态、超时、取消、工具结果和事件；把提供商兼容处理封装在适配层。
4. **MemoryService**：提炼、保存、查询、修订、遗忘记忆，并维护来源、适用范围与索引状态。搜索文档、搜索对话和召回记忆分别返回明确的来源类型。

保留现有 providers 与知识库能力，先从 router 中提取职责；无需先引入新的 Agent 框架。

## 对齐 README 最初方向的记忆设计草案

优先围绕“所有 Chat 内容可编辑、可追溯、可检索”建设，再增加偏好与长期事实记忆。对话档案与提炼记忆分别存储，避免把每句模型回答都提升为长期事实。

- **原始对话与修订**：保留 conversation_id、message_id、revision 和时间，能够回到证据原文。
- **会话滚动摘要**：记录摘要覆盖到的消息与版本，帮助长对话连续；不替代原文。
- **对话检索索引**：对有效版本分块索引；编辑、删除后可重建，结果能定位消息。
- **长期记忆条目**：候选字段为内容、类型、用户/项目/会话范围、来源消息及修订、状态、创建/更新时间、替代关系。用户陈述与模型推断需要区分。
- **用户管理**：提供查看、编辑、禁用、删除，以及本轮采用了哪些记忆的说明。明确自动提炼、自动生效、仅手动记忆的策略。
- **遗忘与冲突**：新旧结论保留替代关系；原消息被改写或删除时，派生记忆进入失效或重新审核流程，索引同步清理。
- **索引边界**：SQLite 保存事实、修订与来源，向量索引可重建；默认仅在本机保存。外部模型提炼和 embedding 仍需调用已配置提供商，不能把“本地存储”解释成“内容不会发送给模型”。

尚需在开始实施前讨论：用户级与项目级范围如何划定、自动记忆默认策略、删除会话时是否保留用户明确保存的记忆。以上是设计建议，尚未实现或定为产品要求。

## 实施顺序与验收

2026-10-21 更新：根据后续讨论，先开展 Agent / Skill 解耦，再接长期记忆。具体职责、配置、运行协议和新阶段顺序以 [Agent 体系设计 v1](../design/agent-system.md) 为准；以下为最初审查时的建议顺序。

1. 修复消息身份、编辑/重生成幂等性、流式完成与持久化语义、切换会话竞态。验收：重试和编辑不重复提问，中止可恢复，保存失败可见。
2. 引入消息修订、统一 ContextBuilder、滚动摘要和预算。验收：普通/RAG 历史策略一致，旧摘要不能覆盖新版本，长对话不靠静默截断丢关键结论。
3. 建立对话索引与来源回溯。验收：跨会话能找到旧结论，修改和删除后检索不返回失效版本。
4. 增加长期记忆 CRUD、范围、提炼与召回。验收：用户能检查与修正记忆，新旧结论可追溯，不相关项目不混入。
5. 抽离 AgentRunner，接入记忆查询等工具。验收：工具循环受预算约束，取消停止后续任务，每次运行可定位所用证据。
