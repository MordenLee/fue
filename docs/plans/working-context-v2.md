# 工作记忆 v2 实施清单

状态：部分完成并纳入 1.0.11 同版本更新。2026-10-21。已完成隔离回归与真实提供商单场景验证；实际证据、调用用量和剩余差距见 [实现与验证](../validation/working-context-2026-10-21.md)。

设计依据：[长对话工作记忆与上下文压缩架构](../design/working-context.md)。现有实现：[聊天记忆与 MCP](../design/conversation-memory.md)。

## P0：用量与上下文选择

- [x] 记录每次主模型、总结/标题及本轮查询嵌入和重排；区分实际、估算及未知用量。
- [ ] 完成后台索引用量关联与全量聚合报表（当前只提供近期记录，无价格估算）。
- [x] 定义输入预算、输出预留、累计调用预算及证据预算，工具定义和协议开销计入输入。
- [x] 从服务器有效历史生成选择清单，记录来源签名、总结版本、材料引用与输入估算；不修改消息正文。
- [x] 对齐普通/RAG、流式/非流式路径；总结默认关闭，显式启用后才在账本预算内运行。
- [ ] 固定文本判断与长对话回忆样例，记录改动前基线，避免用不同模型或不同输入比较费用。

退出条件：一次回答的模型请求数、输入输出及后台调用可追踪；上下文预算能覆盖工具循环，且不静默截断当前问题。

## P1：业务日志、材料状态与精确回读

- [x] 增加 context_events，与已有消息变更日志分别承担职责；提供操作 ID、会话内序号及来源修订。
- [x] 材料绑定完整问答版本，记录用户明确选择的完成/采用状态与结果；聊天仍按问答对索引。
- [x] 明确完成的材料无需模型即可移出全文，保留结果与原文入口；相同查询向量和重复工具请求复用缓存。
- [ ] 单条消息内多材料定位、processing 状态及通用旧证据淘汰。
- [x] 增加 read_memory 与 chat/material/compaction 三类引用；目录分页，直接读取不生成向量。
- [x] 在 MCP 与第一方 Agent 共用同一业务分发器；范围、版本、时间及累计结果预算不可绕过。
- [x] UI 展示真实清理事件并提供原文定位；模型计划不能充当已完成操作。

退出条件：30 份材料判断后能减少重复输入，且任意未删除材料可以在许可范围内精确回读；不产生额外判断模型调用。

## P2：summary.md 与持久压缩

- [x] 用 JSON 保存总结条目、来源签名与有效 head；SQLite 为提交依据。
- [x] 实现限长 MD 投影、原子替换、hash 冲突检测和检查面板时的惰性修复。
- [x] 当前目标、有效标准、已确认结果、待办和历史入口分区；提示词要求区分确认与推断，真实性仍需实际模型评估。
- [x] 按压力阈值从新增原文和已有总结生成候选，保留近期完整问答；不在悬空工具批次中压缩。
- [ ] 自动选择旧来源核对、分区重建及多级摘要，尚不支持。
- [x] 校验来源修订后同事务提交总结与压缩事件；标记覆盖范围、保留边界和回读入口。
- [x] 在输入中注入总结和简短压缩标记；访问策略不允许的来源不得通过总结注入。
- [x] 纳入整轮 token 预算，限定总结尝试次数，失败后不循环付费重试；不承诺金额封顶。
- [x] 编辑/重生成使派生版本失效；主动删除清理日志、索引、材料、总结、MD 和相关派生正文。
- [x] 新开关明确区分旧轮数窗口与新预算模式；不自动总结旧会话，保留标题语义。
- [x] UI 展示压缩状态、总结版本、覆盖目录、实际/估算用量和当前限制。
- [x] 用人工数据完成真实提供商的压缩、精确回读、标准恢复、复用及用量验证，记录失败案例和统计修正。
- [ ] 完成多场景/多次压缩的回忆质量、货币费用和延迟基准。

退出条件：通过设计文档全部验收场景；对比基线给出实际费用、延迟、输入总量与回忆正确率，验证总结开销后再决定默认参数。
