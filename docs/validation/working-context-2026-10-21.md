# 工作记忆 v2：开发实现与验证

2026-10-21。当前为本地开发实现，尚未发布到 GitHub Release。正式版 1.0.11 的安装包不包含这些新增功能。架构依据：[working-context.md](../design/working-context.md)。

## 已接入的实际链路

普通/RAG、流式/非流式四个现有接口共享：

```text
chat.router._prepare：保存提问、绑定权限与每轮 ledger
  → AgentRunner.events
  → memory.working.prepare（仅工作记忆模式）
  → 服务器有效问答 + 材料状态 + 受检验的已有总结
  → 规则清理 / 必要时一次总结模型请求
  → 总结版本、压缩事件、summary.md 投影
  → 模型与工具循环：逐次检查预算及源修订
  → 最终正文、引用与聊天日志保存
```

`agents/usage.py` 记录主模型、总结和标题调用；`providers/telemetry.py` 将本轮账本传递到检索线程，记录查询嵌入和重排的调用估算，并复用同模型、相同查询的向量。适配器未返回实际用量时明确记为未知，以估算显示，不作为零费用。

## 使用方式

1. 重启开发应用，使新 Python 表结构和 Agent 资源加载。正常启动自动创建新增表，不改写现有聊天正文。
2. 设置 → 对话设置 → 长对话上下文模式，选择“工作记忆”。新模式默认关闭；原有轮数模式继续可用。
3. 配置单次/累计输入输出预算、总结长度，并在原有“压缩模型”选择器中明确指定有效模型。
4. 如需压缩，启用聊天历史访问并选择适用范围。禁止历史查询时，系统不会把旧对话压缩成无法回读的总结；超出预算会明确报错。
5. 聊天页展开“工作记忆与执行过程”。在“材料与问答状态”选择已完成的材料，填写要保留的结果/标准/未采用理由，再保存。可以恢复全文进入上下文。
6. 后续请求在新模式下以结果与回读引用替换已完成问答全文；原始消息、版本和问答索引仍保留。接近预算且存在可压缩的较早问答时，才生成总结。
7. 总结、材料结果、压缩记录和最近模型用量均可在面板查看。回读原文/压缩目录需遵守历史查询范围；已知地址不做向量搜索。

不自动启用新模式、不自动选择付费压缩模型、不批量总结旧会话。标题模型仍负责短标题，工作总结使用独立版本；标题输入现在只取本轮问题和回答的短预览。

## 存储与接口

新增 SQLite 表：`context_events`（会话内顺序事件）、`context_summaries`（总结版本与来源签名）、`conversation_materials`（材料状态/结果）、`model_usage`（请求用量）。总结条目及依赖采用 JSON 字段，未另建关系表；来源必须是当前有效、可访问的问答版本。

文件实际位置为 `<应用数据目录>/working_memory/conversations/<id>/summary.md`。单独使用 working_memory 目录，避免开发数据与 backend/conversations Python 包混在一起；目录已从 Git 和安装包资源中排除。

总结正文包含标题、来源引用与五个分区，执行字符/token 双限制；模型返回结构不合法、来源 ID 不合法或超限时拒绝提交，不直接截断。SQLite 为提交依据；文件写入失败显示 pending，检查面板时从数据库修复；外部手改文件显示 conflict，运行时不会自动执行或采纳外部文件内容。

新增用户界面 API：

- `GET /api/memory/conversations/{id}/context?offset=0`：当前总结、每页 20 个有效问答、最近 30 个上下文事件、最近 100 次用量。
- `PUT /api/memory/conversations/{id}/material`：明确设置材料状态、采用状态和保留结果（最多 800 字符）。
- `GET /api/memory/conversations/{id}/read?ref=...&offset=0&length=2000`：本会话引用分页，仍执行历史权限。

新增第一方/MCP 共用的 `read_memory`：接受 `chat:`、`material:`、`compaction:` 引用。压缩入口返回分页目录，不能把目录当作已读全部原文。工具最大单页 4,000 字符，继续共享整轮结果预算。

SSE 在兼容现有协议的同时增加 `[ACTIVITY]` JSON 事件。工具执行、上下文准备、清理、总结和用量不再被 CLEAR 清掉；等待期间每 10 秒发送活跃事件，保持界面状态可见。它仍不是具有断线续读能力的持久 Run 协议。

## 一致性和预算

- 总结前后核对完整消息/材料指纹与有效 head。编辑或删除发生后，晚到候选不能提交；每次主模型调用前再检查来源与历史访问策略。
- 编辑、重新生成、材料结果变更使当前总结失效。主动删除会保守清理该会话所有派生总结、材料、上下文事件、用量和 MD 文件；原有问答/Chroma 删除逻辑继续生效。
- 文件删除失败不报告完整删除成功；数据库可回滚。多存储并非分布式事务，后续检查可修复文件投影。
- 单次输入预算计入工具 schema、消息结构与证据；累计预算包含本轮实际经过账本的主回答、总结、标题及检索调用。接近累计预算时停止扩展工具，预留最终回答机会。
- 输入按 UTF-8 长度近似估算并预留余量；实际提供商用量返回后校正累计值。不是精确 tokenizer，也不是硬性金额封顶。SDK/提供商内部重试、未返回的推理/缓存用量可能使账本不完整。
- 一次准备最多发起一次总结请求；失败、中止或来源冲突后不进行付费重算循环。请求发出后取消不能保证提供商不计费。

## 本地验证

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
npm --prefix frontend run typecheck
npm run build
```

目前 48 项 Python 测试通过，包括 13 项新增工作记忆测试；TypeScript 检查与 Electron 生产构建通过。

新增测试使用临时工作目录、真实隔离 SQLite、假模型及本地文件，覆盖：

- 四个真实 HTTP 聊天入口接入工作上下文并保存用量。
- 总结生成、字符限制、来源验证、MD 文件与压缩目录/原文回读；后续请求可复用总结而不再次调用总结模型。
- 30 份材料规则清理后输入估算小于原始材料的一半，无总结/嵌入请求；这只是人工样例结果，不是实际费用承诺。
- 材料恢复、disabled 与时间范围、超长总结拒绝且不重试。
- 编辑期间的晚到候选、中止总结、同步删除及文件删除失败回滚。
- MD 写入失败后的恢复、外部文件冲突，以及检索线程中同一查询向量的复用。

隔离 Electron 页面交互验证了：展开工作记忆面板、保存材料结果、回读原文、展示总结/用量、显示新预算设置。测试使用人工接口数据，阻止全部外部网络请求；不是连接真实提供商的完整桌面验收。

## 尚未覆盖的范围

- 材料先以完整问答为单位，由用户明确标记；尚无自动“无关材料”判定、单个消息内多材料定位或 processing 状态工作流。
- summary.md 在首次成功压缩时生成，未达到阈值时显示“尚未压缩”；不是每轮额外请求模型生成一份总结。
- 总结使用当前总结加新增原文；未实现自动选择旧来源进行语义核对或多级摘要重建。对超大单条材料/超出压缩模型窗口的历史明确拒绝，需缩小批次或先标记材料。
- 默认预算和压缩阈值仍需真实提供商、明确费用范围内的回归验证；未验证真实模型多次压缩后的事实/标准保留准确率。
- 后台历史索引任务没有归到具体聊天 Run 的账本；界面用量只列近期记录，无货币价格表或全量聚合报表。
- 上下文事件保存来源选择与版本；尚未提供确定性重放接口、请求恢复、完整分支导航或手工总结编辑器。
- 窗口很小、历史访问被禁止、来源超出时间范围、未指定有效压缩模型等情况会明确停止，不静默丢弃早期内容。
