# FUE 学术写作功能需求（草案）

> 状态：讨论稿，当前先交付应用内的基础写作窗口 · 2026-10-05  
> 目的：先明确产品需要做什么，再决定编辑器选型和实现方式。

## 1. 产品目标与范围

FUE 的写作功能主要面向**带有引用标签的学术论文**。核心工作方式是：**用户始终可以直接编辑完整正文，同时通过侧边聊天查找、讨论和修改论文内容。**

第一阶段交付一个可靠的单人写作工作台。知识库检索、模型配置和聊天能力沿用 FUE 已有体系；写作正文是独立于聊天记录、知识库原始资料的用户文稿。

**当前开发目标**是在 FUE 页面中直接提供可编辑、可保存的正文窗口，详见[开发清单](../plans/chat-write-development.md)。采用开源 Tiptap/ProseMirror 编辑内核；文稿由 FUE 管理，内部存储为结构化编辑数据，用户无需维护固定的 Markdown 或 Word 源文件。日常排版预期采用类似 Obsidian 的轻量操作；表格、图片、脚注、公式和参考文献暂不进入当前阶段。

## 2. 主要使用流程

1. 新建或打开文稿，输入标题，直接写作和排版。
2. 离开文稿后重新打开，正文和最近的编辑状态仍在。
3. 在章节侧边栏定位内容，或通过聊天要求 AI 在全文中查找需要修改的位置。
4. 在正文中像审阅代码差异一样查看 AI 的新增和删除，按处或按组接受/拒绝；继续手动编辑或恢复先前版本。
5. 完成后导出 Word 与 LaTeX 交付文件。

## 3. 候选功能范围（基础编辑验证后重排优先级）

### 3.1 文稿管理

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| DOC-01 | 新建、打开、重命名、删除文稿 | 文稿有独立标题和正文；删除前确认；重新启动应用后仍可访问未删除文稿。 |
| DOC-02 | 文稿列表 | 复用 FUE 已有的文件夹/列表侧边栏组件；可看到标题与最近修改时间，并能快速切换文稿。 |
| DOC-05 | 文稿表示 | 文稿由应用管理，不要求用户维护一个固定的 `.md`、`.doc` 或 `.docx` 源文件；使用可扩展的结构化正文表示。 |
| DOC-03 | 自动保存与状态提示 | 停止输入后自动保存；界面能区分“保存中”“已保存”“保存失败”；保存失败不能悄然丢稿。 |
| DOC-04 | 恢复未完成编辑 | 应用正常关闭再启动后可继续写作；异常中断后的恢复策略需要实现并验证。 |

### 3.2 基础文本编辑

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| EDT-01 | 稳定输入与选区 | 支持中文输入法、键盘导航、跨段选择、复制、剪切、粘贴；输入过程中光标不跳动。 |
| EDT-02 | 基础排版 | 交互以类似 Obsidian 的轻量排版为目标：段落、各级标题、加粗、斜体、无序/有序列表、引用块、链接及常用输入规则。 |
| EDT-03 | 撤销与重做 | 手动编辑可以按常见快捷键撤销/重做；接受一次 AI 修改后可整体撤销该次修改。 |
| EDT-04 | 查找与替换 | 在当前文稿内查找文本、逐个或全部替换。 |
| EDT-05 | 章节侧边栏 | 正文作为一篇连续的大文稿编辑；侧边栏根据章节标题生成大纲，点击标题跳转，不把章节变成独立文件或必须单独保存的内容块。 |
| EDT-06 | 编辑体验 | 正文有清晰的阅读宽度、段落层次和明暗主题；窄窗口下仍能专注编辑。 |
| EDT-07 | 学术内容 | 支持表格、图片、脚注、行内及独立公式、正文引用标签和参考文献列表的编辑、显示与保存。 |
| EDT-08 | 引用关联 | 正文引用标签与参考文献条目保持关联；修改编号、移动段落或导出时不丢失来源关系。引用样式与编号规则可配置的具体范围待定。 |

### 3.3 一边聊天，一边写作

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| AI-01 | 同屏工作 | 正文与写作聊天可同时查看；聊天面板可调整宽度或收起。 |
| AI-02 | 明确上下文 | 可对选中文本、当前章节或全文提问；发送前能看清本次作用范围。 |
| AI-03 | 讨论与修改分流 | 普通问答只产生聊天回复；需要修改正文时生成明确的修改建议，不因聊天回复自动改稿。 |
| AI-04 | 全文定位与修改 | 支持根据自然语言指令在全文自动定位一处或多处目标，并修改对应内容；每处改动可以回到原文位置查看。 |
| AI-05 | 修改审阅与冲突保护 | 全文修改以差异审阅形式展示新增、删除及改动位置；可逐处或按组接受/拒绝，并能撤销或恢复。AI 生成期间正文仍可编辑；若目标被用户改动，不能无提示覆盖。 |
| AI-06 | 会话关联 | 写作聊天与文稿关联；重新打开文稿可以继续查看对应讨论及已接受的修改记录。 |
| AI-07 | 学术结构保护 | AI 修改后，引用标签、脚注、公式、图片、表格及其关联不能无提示丢失或错位；无法保证时必须提示用户检查。 |
| AI-08 | 引用来源 | 可使用 FUE 知识库资料辅助写作；写入正文的引用必须能追溯到对应资料，并与文末参考文献关联。 |

### 3.4 版本与交付

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| VER-01 | 可恢复版本 | 定期保存版本，并在接受 AI 修改前保留可恢复状态；可查看时间和恢复指定版本。 |
| EXP-01 | Word 导出 | 首发支持现代 Word `.docx` 和旧版 Word `.doc`。“能打开”之外，要核对标题层级、表格、图片、脚注、公式、引用标签和参考文献，并明确旧版格式的保真限制。 |
| EXP-02 | LaTeX 导出 | 首发支持导出可继续编辑/编译的 LaTeX 工程或文件；正文结构、公式、图表、脚注与引用需有可检查的映射。可研究大模型辅助转换，但结果需验证。 |
| EXP-03 | 数据可带走 | 文稿即使不是单个源文件，也要能通过导出或备份带走正文、图片和引用数据。 |

## 5. 数据与质量要求

- **正文独立**：文稿不是一条聊天消息，也不是知识库中的只读资料；删除会话不应误删文稿。文稿在应用内可以是结构化数据，而不是固定的单个 Markdown 或 Word 文件。
- **显示与语义分开**：HTML 负责编辑与显示；标题、引用、脚注、公式、图片等必须保留可识别的语义和关联，不能只依赖最终显示出来的字符与样式。
- **修改可追溯**：AI 的生成内容、待审阅改动和已接受的正文有清楚的状态区分。全文自动定位后的增删改以差异形式审阅，可逐处或按组决定，并可撤销。
- **不丢稿**：切换文稿、切换页面、关闭窗口、保存失败和请求中断时，未保存的内容必须有明确处理。
- **本地优先**：沿用 FUE 桌面应用的本地数据模式。向模型发送正文时，应按任务范围发送必要内容，并让用户知道作用范围。
- **性能**：长文输入、滚动和切换不应出现明显卡顿；需要用真实长度文稿验证，而不只用短示例。
- **可访问性**：基础编辑、工具栏、聊天与修改接受操作可以用键盘完成。

## 6. 与现有 FUE 的关系

目前已有会话、模型选择、流式聊天、知识库检索和引用展示，可作为写作聊天的基础。当前项目尚无独立的可编辑文稿模型、写作页面、文稿版本与交付导出流程。知识库文档主要是检索资料，不能直接充当用户正在写的正文。

## 7. 需要确认的产品决策

已确定的产品方向：学术论文是主要交付物；连续正文配章节侧边栏；全文自动定位与差异审阅；目标导出格式为 `.docx`、`.doc` 和 LaTeX。当前先验证应用内的开源编辑内核与基础写作体验，再决定学术元素、AI 审阅和导出的开发优先级。编辑时渲染为 HTML，内部保留结构化正文。

仍需确认的问题：

1. **引用规范**：首版必须支持哪些标签形式和文献样式？引用目标来自知识库文档、手工建立的文献条目，还是两者都需要？
2. **LaTeX 交付标准**：只要求导出 `.tex`，还是要求图片、`.bib`、依赖文件齐全并能编译？
3. **导入优先级**：首版必须打开已有 DOCX，还是可以先从新建文稿开始？
4. **排版保真边界**：Word/LaTeX 导出是否要求与编辑界面视觉一致，还是以学术语义、可编辑和可编译为主要验收标准？
5. **旧版 Word 保真边界**：`.doc` 对公式、引用及复杂排版的降级方式需要明确验收样例。

## 8. 完整产品流程示例（非当前验证范围）

用户可以完成“新建论文 → 在连续正文中写多个章节，并插入表格、图片、脚注、公式和引用 → 自动保存并重新打开 → 要求 AI 在全文定位多处内容 → 审阅新增/删除并逐处或按组接受/拒绝 → 导出 `.docx`、`.doc` 和 LaTeX”的完整流程。导出后引用与参考文献仍可对应，正文结构和学术元素没有静默丢失。
