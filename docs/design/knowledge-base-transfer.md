# 知识库 JSON 迁移（携带向量）

## 使用方式

在知识库详情点击导出按钮，保存单个 JSON；在目标 FUE 的知识库列表标题旁点击“导入 JSON”，选择文件与本地嵌入模型，可填写新名称。导入始终新建知识库，不覆盖或合并现有数据。

界面预览源模型、向量维度、文档与分块数量。导入期间显示状态，完成后选中新知识库。后端执行完整校验；前端预览不作为校验依据。

导入和导出均不调用模型：直接复用已经处理的 chunk 和向量，因此不产生重新清洗、元数据提取或嵌入的 token 消耗。之后执行语义查询和生成回答仍有正常的模型费用。

## 内容与格式

交换格式标识为 `fue-knowledge-base`、`format_version: "2.0"`。这是文件格式版本，本次应用版本为 2.0.0；两者独立管理。

- 知识库名称、描述、分块参数及分隔符选项。
- 文档来源 ID、文件名、文件类型、摘要、完整引用字段。
- 按文档组织的 chunk，包含连续序号、处理后的文本与向量。
- 嵌入配置、来源记录状态、向量维度与 SHA-256 完整性校验。

源文档 ID 仅用于包内标识，导入时分配本地 ID 并重建 Chroma 元数据。同名文档保持独立。关键词搜索、语义检索、引用和前后 chunk 阅读均复用现有接口。

**不包含**原始 PDF/图片等附件、提供商密钥、原电脑文件路径、聊天历史、研究任务、文件夹与重排模型设置。旧索引未独立持久化完整清洗文本，本格式保存实际检索 chunk，不拼接伪造原文。导入文档没有原始附件，因此拒绝单篇和批量重新索引，保护现有向量；需要重新处理时先上传原文件。

仅导出所有文档都已完成索引的知识库，遇到处理中或未完成文档会给出提示。空知识库可迁移。单文件上限 256 MiB，导入与导出使用同一上限；当前实现会在内存中处理 JSON，不定位为超大规模数据库备份。

## 模型兼容性

比较模型 API 名称、接口类型、服务地址的 SHA-256 指纹、归一化模式。服务地址不以明文导出。不同配置直接拒绝导入，不用“维度相同”推定向量可兼容，也不自动调用模型探测。

新建索引记录生成时的配置到 collection 元数据，导入时保留它；旧索引没有该记录，导出标记为未验证，导入必须由用户勾选确认所选模型与原索引一致。确认后仍保留未验证标记，不能在再次导出时升级成已验证。

这里的“已验证”表示**记录了生成配置**，并不保证远端服务未更新模型权重。当前模型配置没有不可变修订号，`revision` 为 null，归一化为 `provider_default`。同一地址同名模型的服务端变化无法靠离线 JSON 验证；不能将这些字段解释为对模型权重的证明。

已有向量时，知识库不能切换到不兼容的嵌入配置。旧 1.0 文件缺少文档 ID、引用和校验信息，此入口要求从原知识库重新导出为 2.0，不猜测补全旧数据。

## 一致性和失败处理

导入在写入前校验格式、摘要校验和、文档 ID 唯一性、连续 chunk 序号、非空文本、有限且非零向量、float32 数值范围与统一维度。SHA-256 用于发现损坏，不是来源认证或签名。

SQLite 记录在 Chroma 分批写入完成后才提交。发生异常时回滚 SQLite 并删除新 collection；使用随机 collection 名称，防止重用数据库 ID 时误接入旧向量。不修改原知识库。

SQLite 与 Chroma 不支持跨库原子事务：若进程被强杀，可能留下没有 SQLite 记录引用的孤立 collection，但不会出现列表中可用的半成品知识库。这类残留的自动清理和超大文件流式导入不在本次实现中。

## API 与代码边界

- `GET /api/knowledge-bases/{id}/export`：下载 JSON。
- `POST /api/knowledge-bases/import`：multipart 字段 `file`、`embed_model_id`、可选 `kb_name` 和 `confirm_unverified`。
- Core：`knowledge/transfer.py` 负责格式、校验、模型配置及迁移事务；路由负责上传与下载。
- Studio：`KBImportForm` 提供选择文件、预览、模型选择和进度状态；复用知识库导出入口。
- 本次不扩大外部 Agent 的写入权限。

## 验证

`tests/test_knowledge_transfer.py` 使用隔离 SQLite 与真实 Chroma，阻止模型工厂调用，验证携带向量的 HTTP 往返、中文名称、同名文档、引用、关键词检索、邻接阅读、向量查询、非法包拒绝、模型不匹配、旧来源确认、失败回滚与重新索引保护。
